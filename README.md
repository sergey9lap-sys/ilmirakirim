# Сайт Ильмиры Кирим

Самостоятельная копия актуальной страницы из `personal-world/sites/ilmira`, перенесённая 23 сентября 2026 года. Прежняя версия по `/p/ilmira` остаётся в `myworld` и не изменена. Репозитории не синхронизируются автоматически. Основной домен — `ilmirakirim.com`; `.ru` перенаправляется на него на стороне хостинга.

## Размещение

`index.html` и медиа остаются статическими. Для сохранения заявок теперь требуется сервис `server/index.mjs` на Node.js 22.16+ и SQLite из `node:sqlite`. Сборка сайта и установка npm-пакетов не нужны. Публичный веб-сервер продолжает отдавать статические файлы, а пути `/api/` и `/cabinet/` направляет на сервис, слушающий только `127.0.0.1:4314`.

Для будущих отдельных страниц можно добавлять каталоги вида `имя-страницы/index.html`, сохраняя главную страницу в корне.

## Заявки и доступ Ильмиры

- Кнопки мессенджеров в обеих формах сперва отправляют контакты на `/api/leads`, затем открывают привычный чат. При ошибке сохранения чат не открывается, посетитель получает понятное сообщение.
- Заявки пишутся в `DATA_DIR/leads.sqlite`; `DATA_DIR` должен быть абсолютным путём **вне каталога сайта** на российском сервере. Не размещать базу, `.env`, резервные копии или секреты в Git, `public_html` либо доступном из интернета каталоге.
- `/cabinet/` — закрытый список заявок. Вход только один, для Ильмиры, по длинному паролю. Сессия действует 8 часов. Административный API защищён от чтения без входа, перебор пароля ограничен.
- После сохранения в базе создаётся запись в очереди уведомлений. Если Telegram недоступен, сервис повторит отправку. В Telegram уходит только номер заявки и ссылка на вход, без имени, телефона и почты клиента. Пока бот не подключён, заявки всё равно сохраняются, уведомления остаются в очереди.
- Перед боевым запуском проверить тексты документов о персональных данных с юристом, локацию **сервера и резервных копий**, ограничение доступа и HTTPS.

### Подготовка сервера

1. Проверить `node --version` — нужна версия **22.16 или новее**. На текущем сервере проверены Node.js 22.23.2 и наличие встроенных SQLite API; обновление не требуется.
2. Создать отдельного системного пользователя для сервиса и закрытый каталог данных, например `/var/lib/ilmira-leads` с правами `0700`. Каталог резервных копий держать вне веб-корня, в подтверждённой российской локации.
3. Создать секретный файл окружения **на сервере**, не в репозитории, по образцу `.env.example`. `PUBLIC_ORIGIN` должен быть строго `https://ilmirakirim.com`.
4. Ильмира выбирает пароль длиной от 16 символов. Его хеш можно сгенерировать локально или на сервере, передав пароль через stdin в `node server/hash-password.mjs`. В `ADMIN_PASSWORD_HASH` записывается только полученный хеш; исходный пароль никуда не отправлять и не коммитить.
5. Запустить `node server/index.mjs` под отдельным пользователем через systemd с `NODE_ENV=production`, `HOST=127.0.0.1`, `PORT=4314`, `DATA_DIR`, `ADMIN_PASSWORD_HASH`. Пример службы — `deploy/ilmira-leads.service.example`; путь к Node и проекту скорректировать по серверу.
6. К существующему HTTPS-конфигу Nginx добавить маршруты из `deploy/nginx-locations.conf.example`. Не заменять весь конфиг и не менять действующий редирект `.ru` → `.com`. Затем проверить и перезагрузить Nginx.
7. До включения публичных кнопок проверить запись тестовой заявки, вход в `/cabinet/`, отсутствие данных без входа и восстановление из резервной копии. При обновлении сайта применять изменения статических файлов и сервиса **вместе**: новые кнопки требуют работающего `/api/leads`.

Для Telegram Ильмира создаёт бота через BotFather и нажимает у него «Старт». `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` указываются только в секретном файле окружения на сервере. Позже уведомитель можно заменить на почтовый, не меняя базу и форму.

`server/backup.mjs` делает консистентную копию SQLite в `BACKUP_DIR`. Примеры ежедневного расписания — `deploy/ilmira-leads-backup.service.example` и `deploy/ilmira-leads-backup.timer.example`; их нужно установить как системные unit-файлы и включить timer. Периодически проверять восстановление. **Сам скрипт не гарантирует российскую локацию внешних бэкапов** — это отдельная настройка хостинга. Простое копирование открытого `.sqlite`-файла вместо этого скрипта не использовать.

Локальные проверки: `node --test tests/leads.test.mjs tests/metrika-consent.test.mjs`. Для запуска сервиса вручную сначала задать переменные окружения; отсутствие `DATA_DIR` и `ADMIN_PASSWORD_HASH` намеренно блокирует старт.

## Яндекс.Метрика

Счётчик `113009416` подключён в `app.js` с настройками, выданными Метрикой. Он запускается только на `ilmirakirim.com` и `www.ilmirakirim.com` после нажатия «Согласиться» в уведомлении о cookie; закрытие уведомления не запускает аналитику. На локальных адресах счётчик отключён, чтобы тестовые визиты не попадали в отчёты. Поля имени, почты и телефона помечены `ym-disable-keys` для Вебвизора.

`noscript`-пиксель из стандартного кода сознательно не установлен: без JavaScript сайт не может получить и проверить выбор посетителя по cookie-уведомлению. Если механизм согласия изменится, пересмотреть этот пункт отдельно. После публикации открыть `https://ilmirakirim.com/?_ym_debug=2`, нажать «Согласиться» и проверить номер счётчика и PageView в панели отладки. Автоматическая проверка без нажатия на cookie-уведомление может не обнаружить отложенный счётчик.

## Домен

- В canonical, Open Graph, структурированных данных, `robots.txt` и `sitemap.xml` указан согласованный адрес `https://ilmirakirim.com`.
- Перед открытием сайта проверить настройки DNS, HTTPS и работу всех ссылок, форм и документов на новом сервере. Изменение репозитория само по себе не размещает сайт на хостинге.
- Копирование в этот репозиторий не обновляет прежнюю страницу автоматически; дальнейшие правки для нового домена вносить сюда отдельно.
